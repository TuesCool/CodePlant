# CodePlant MI14 Phone Agent — v0.2 系统扩展与平台接入架构说明

> **版本状态**：`v0.2.0`（2026-11-27）  
> **同步仓库**：[`TuesCool/CodePlant`](https://github.com/TuesCool/CodePlant) (`phone-agent/`)  
> **核心理念**：无 Root、无安全调试下的小米 14 端侧个人 AI 管家 —— 控屏链路闭环、免费与缓存模型路由、个人知识库与生态平台统一桥接。

---

## 一、v0.2 核心修复：MI14 自动控屏与微信发消息闭环

### 1.1 原问题根因
1. **无应用名到包名检索**：Agent 打开陌生 App（如音乐播放器、备忘录）时无法获知系统实际包名。
2. **仅坐标点击稳定性低**：不同分辨率/键盘状态偏移导致仅用 `phone_tap(x, y)` 容易点偏。
3. **无聚焦直接输入失败**：`ACTION_SET_TEXT` 在未对准目标输入框坐标/节点触发点击聚焦时，微信等第三方输入框不会接管焦点。
4. **HyperOS 后台弹出界面限制**：从 Termux / 本地 Web 发命令后台唤醒其他 App 时，若未开启「后台弹出界面」，`startActivity` 会被 MIUI/HyperOS 静默拦截。

### 1.2 v0.2 解决方案
- **Android Portal (`0.2.0`)**：
  - 新增 `GET /apps`：扫描桌面可启动应用并返回 `{ label, packageName }` 映射。
  - `PortalAccessibilityService` 缓存最近一次控件树节点列表 (`lastNodes`)，支持按节点索引 `[index]` 直接触发 `ACTION_CLICK`（`tap_element`）。
  - `inputText(text, targetX?, targetY?)` 改为挂起协同流程：先点击并聚焦目标坐标/节点，延迟稳定后尝试 `ACTION_SET_TEXT`，失败则自动回退到系统剪贴板 + `ACTION_PASTE`，中文输入稳定可靠。
  - `open_app` 支持按 `appName`（如 `"微信"`、`"网易云音乐"`）或 `packageName` 启动，若被 HyperOS 拦截则返回明确授权提示。
- **pi-server 工具链升级 (`phone-tools.ts`)**：
  - 新增 `phone_list_apps`、`phone_tap_element`、`phone_wait`，并升级 `phone_open_app` / `phone_input_text`。
  - 在 `buildStaticSystemPrompt()` 中固化标准 5 步控屏链路：`phone_list_apps` → `phone_open_app` → `phone_wait` → `phone_get_screen` → `phone_tap_element` / `phone_input_text(index)`。

> **手机端关键前置权限检查**：  
> 1. 小米设置 → 应用设置 → 应用管理 → `CodePlant Portal` → **权限管理 → 后台弹出界面：务必设为「始终允许」**；  
> 2. 无障碍服务开启 `CodePlant Portal`；通知使用权开启 `CodePlant Portal`；省电策略设为「无限制」。

## 三、基于 Pi 实现的 Prompt Cache 省 Token 架构 (`cache-manager.ts`)

### 3.1 三档缓存梯度与具体数值参数
`PromptCacheManager` 将策略映射到 `@earendil-works/pi-ai` 的 `SimpleStreamOptions.cacheRetention`（`"none" | "short" | "long"`）及本地上下文锁定策略：

| 梯度 | `pi-ai cacheRetention` | 默认最小前缀阈值 (`minPrefixTokens`) | 前缀保持不压缩轮数 (`batchHoldTurns`) | 适用场景 |
| :--- | :--- | :--- | :--- | :--- |
| **低 (low)** | `none` | `1024` | `4` | 零碎短问答、模型不支持或无需长上下文保持 |
| **中 (medium)** | `short` | `2048` | `8` | 日常手机管家 + 待办调度 + 多步控屏（默认推荐） |
| **高 (high)** | `long` | `4096` | `14` | 连续读知识库、深度代码/研究分析、Claude/DeepSeek 高频会话 |

### 3.2 针对不同模型的最佳命中建议与前缀锁定
- **前缀不变锚点 (`buildStaticSystemPrompt`)**：系统核心规则、个人偏好 `preferences.md` 和 App Skills 作为静态系统提示词固定在消息最前方；本地知识库动态召回片段附在用户输入末尾，**避免每轮变更系统前缀而导致缓存失效**。
- **实时遥测统计**：监听 `pi-agent-core` `message_end` 中的真实 `usage`（`input`、`cacheRead`、`cacheWrite`），在顶部与配置页实时显示命中读取 token 数与累计命中率 `%`。
- **分厂商实测提示**：
  - **DeepSeek / OpenAI**：前缀 ≥ 1024 tokens 自动命中；
  - **Claude (Anthropic)**：显式 300s / 3600s 断点缓存，推荐 ≥ 2048 tokens；
  - **Gemini**：隐式前缀缓存通常在 ≥ 2048 tokens 时收益稳定；
  - **部分免费 Flash 渠道**：若服务端不返回 `cached_tokens` 统计字段，命中显示为 `0%` 属渠道限制。

## 四、秘塔 AI 检索下载、个人知识库与 6 大平台接入策略矩阵

### 4.1 秘塔 AI（Metaso）检索与本地导出 (`metaso-client.ts`)
- 接入秘塔搜索 API（配置 `METASO_API_KEY`），支持切换检索域：`webpage`（网页）/ `document`（文库）/ `scholar`（学术）。
- 每次检索自动生成格式化 `.md`（含 AI 综合摘要与原始来源链接）与 `.json` 至 `data/downloads/`，通过 `GET /api/downloads/:name`（带 `Content-Disposition: attachment` 安全校验）供小米浏览器直接下载保存。

### 4.2 个人知识库与平台接入策略矩阵 (`kb-store.ts` & `connectors.ts`)
> **重要设计原则**：**所有平台接入能力均解耦于独立连接器层，不绑定或受限于特定 LLM 模型。** 只要平台本身提供官方 API，任何大模型（DeepSeek / Qwen / GLM / ChatGPT）都可通过工具调用。

| 平台 | 接入策略 | 认证方式 | 当前支持能力 | 限制与替代路线说明 |
| :--- | :--- | :--- | :--- | :--- |
| **本地 KB** | 本地文件系统 (`data/kb/*.md`) | 无需鉴权 | 增删改查、关键词检索、对话自动注入、Agent 工具写入 | 全离线，作为所有同步数据的统一落盘仓库 |
| **Obsidian** | **本地 Vault 直读 + Local REST API** | Vault 路径或 Bearer Token | 连通检测 + 一键同步 `.md` 到本地 KB | 手机端将 Vault 放在 `/sdcard/Documents/Obsidian` 并给 Termux 存储权限即可零插件直读 |
| **语雀 Yuque** | **官方 REST API v2** | Personal Access Token (`X-Auth-Token`) | `/api/v2/user` 连通校验 + 个人知识库目录抓取写入本地 KB | 不受模型限制，需遵守语雀 API 速率限制 |
| **飞书 Feishu** | **官方 OpenAPI v3 + 群 Webhook** | `App ID + App Secret` 或 Webhook URL | 获取 `tenant_access_token` 校验连通 + 后续文档/消息推送基础 | 若需读取飞书云文档/知识库，在飞书开放平台为应用开启对应 `docx`/`wiki` 权限即可 |
| **Notion** | **官方 REST API (`2022-06-28`)** | Internal Integration Token (`Bearer`) | `/v1/users/me` 鉴权校验 + `/v1/search` 页面同步到本地 KB | 需在 Notion 目标页面右上角 `Connections` 添加该 Integration |
| **Gemini Notebook (NotebookLM)** | **MCP Bridge + 无障碍控屏协同** | `notebooklm-mcp` 端点 / 常用链接 | 配置持久化 + 状态管理 + 浏览器/控屏协作 | **Google 暂无通用公开消费端 REST API**，不强行伪造私有接口，采用 MCP 桥接 + 控屏协同 |
| **腾讯 ima 知识库** | **MCP Bridge + 无障碍控屏协同** | `ima-kb-mcp` 端点 / KB ID | 配置持久化 + 桥接入口 + 控屏检索 | **腾讯 ima 暂无免鉴权开放 REST API**，推荐使用开源 MCP Bridge 或交由手机控屏操作 |

## 五、网络监听、共享端口映射与个人网站桥接 (`network-bridge.ts`)

为满足后期接入个人独立网站、其他设备控台或自动化服务，v0.2 内置了统一网关控制面：

1. **监听模式切换**：支持 `127.0.0.1`（仅手机本机，安全默认）与 `0.0.0.0`（局域网 / 内网穿透如 Cloudflare Tunnel / Tailscale / frp / cpolar 共享暴露）。
2. **动态跨域控制 (CORS)**：支持填写允许调用本机的个人网站 Origin 列表。
3. **统一对外桥接端点 (`/api/bridge/*`)**：
   - `GET /api/bridge/manifest`：返回当前暴露端口清单、公网/隧道基础地址与支持动作描述。
   - `POST /api/bridge/invoke`：供你的个人网站直接发起远程调用（若设置了 `Bridge Bearer Token`，强制校验 `Authorization: Bearer <token>`），支持：
     - `action: "todo.add"`：外部网页一键写入手机待办；
     - `action: "kb.search"`：外部网页检索手机个人知识库；
     - `action: "chat"`：外部网页远程触发 MI14 Agent 指令。
4. **出站 Webhook (`outboundWebhookUrl`)**：每次 Agent 任务执行完毕后自动将摘要与缓存遥测结果 `POST` 推送到你的自建网站后端。
